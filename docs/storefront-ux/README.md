# Storefront UX — Research & Daily Design Logs

**Figma:** https://www.figma.com/design/nWfOrtJm3nIEGTDTRGrBDq  
**Schedule:** Daily at approximately 05:00, Africa/Lagos.  
**Purpose:** Provide an auditable, durable handoff between research-led UI/UX design iterations.

## Read before each run

1. Read the latest dated log here and the existing project documents: `docs/DESIGN.md`, `docs/WIREFRAME_BUILD_SPEC.md`, `docs/WIREFRAME_PROGRESS.md`.
2. Inspect the live Figma file to understand what actually exists before changing it.
3. Research production storefronts and credible UX studies. Capture source URLs and specific observed patterns; distinguish observations from proposed design choices.
4. Select a high-impact usability issue and implement a tangible improvement in editable Figma frames/components.
5. Check relevant desktop/mobile layouts, user journeys, responsive behavior, accessibility and edge/error states. Report what was not validated.
6. Add or update today's `YYYY-MM-DD.md` entry in this directory and commit via a pull request if repository protections require it.
7. Summarize the changed Figma nodes, design rationale, evidence, outcomes and next priorities for the following run.

Do **not** claim a Figma modification, research finding, successful test, GitHub commit or merge unless it has been verified. Avoid invented products, prices, shipping policies and brand decisions; mark placeholders clearly. Preserve approved designs and avoid repeating previous work.

## Standard daily log template

```markdown
# Storefront UX — YYYY-MM-DD

- Run status: Complete / Partial / Blocked
- Run date/time (Africa/Lagos):
- Figma page and specific nodes:
- GitHub branch / commit / PR:

## Starting state
What existed, including unresolved issues from the previous run.

## Research and references
- [Source name](URL) — specific observed pattern and applicability

## UX problems prioritized
- User impact, evidence, and why this was prioritized

## Actual design changes
- Screens/components, before → after, design rationale

## Validation
- Screen sizes, flows, accessibility checks, findings, limitations

## Decisions and assumptions
- What is verified; what remains provisional

## Next iteration
- Specific actionable priorities and blockers
```

The Figma file is the design source of truth; these logs provide the evidence and history. Use pull requests to respect protected branches.
