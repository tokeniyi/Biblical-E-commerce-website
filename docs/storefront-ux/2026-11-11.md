## Research and evidence

- [Crossway — ESV Large Print Bible](https://www.crossway.org/bibles/esv-large-print-bible-tru-11/) — reference product shows 10.5-point type, double-column layout, 6.5 × 9.25-inch dimensions. Supports displaying type size and dimensions alongside edition format.
- [Crossway — ESV Pocket Bible](https://www.crossway.org/bibles/esv-pocket-bible-tru-2/) — reference product shows 6-point type, double-column layout and approximately 3.25 × 5.26-inch dimensions. The contrast demonstrates why format names alone do not communicate readability.
- [Crossway — ESV Thinline Bible](https://www.crossway.org/bibles/esv-thinline-bible-red-letter-tru-9/) — product detail distinguishes binding, page layout, features, type size and dimensions; supports structured specification comparison.

These are **external publisher reference products**, not verified inventory, selectable SKUs, prices, stock or business policies for this store.

## UX problem prioritized

The previous catalog concepts let users filter by translation/format, but did not explain the trade-off between text size and portability at the product-detail stage. This could lead shoppers to select an unsuitable edition based on its label alone. The original C05 wireframe also requires unavailable combinations to disable purchase and offer alternatives.

## Changes made in editable Figma

1. Created desktop product-detail exploration `5:2`: translation selector, large-print/pocket comparison, explicit type-size/dimension metadata, illustrative cover, non-live availability area, disabled add-to-cart and a structured comparison table.

3. Created recovery-state exploration `5:73`: unavailable option combination, change/clear selection affordances, illustrative alternative, and no-matching-filters recovery.
4. Preserved the existing blue/neutral design direction and clearly labelled unverified product imagery and commercial data.
