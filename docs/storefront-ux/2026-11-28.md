## Research and references

- [Christianbook — Bibles](https://www.christianbook.com/page/bibles): the page separates translation discovery from Bible-type browsing (including Study, Journaling, Large Print, Devotional, Reference and Compact). This supports keeping translation, type and physical format as distinct attributes rather than one combined facet.
- [Nike — Men’s Shoes](https://www.nike.com/w/mens-shoes-4ff6cz5y0tkznik1zy7ok): the live listing groups filters by attribute families such as gender, offers, color, price, size, brand, collections, sports, shoe height and closure. The transferable observation is clear grouping of relevant facets, not the apparel values.
- [Crossway — ESV Single Column Heritage Bible](https://www.crossway.org/bibles/esv-single-column-heritage-bible-tru/): its product page exposes format/binding, type size, page layout, page count, dimensions, weight, ISBN and edition features. The page identifies this edition as out of print, so it is used only as a specification-field reference, not as evidence of current availability or pricing.
- [Apple — Compare iPhone models](https://www.apple.com/iphone/compare/): the comparison page offers a model selector and aligned feature/specification rows. The relevant pattern is consistent side-by-side attribute alignment; no Apple layout is copied.
- [Baymard — Have Filters for All Displayed List Item Info](https://baymard.com/research-articles/have-filters-for-list-item-info): explains that attributes shown in result items should also be available as filters where relevant, so shoppers can narrow the list by information already exposed.
- [Baymard — Product Page UX 2026](https://baymard.com/research-articles/current-state-ecommerce-product-page-ux): emphasizes clear product options, product information, availability and purchase decision support; this is relevant to keeping C03 card attributes consistent with C05 variant specifications.
- [NN/G — UX Guidelines for Ecommerce Product Pages](https://www.nngroup.com/articles/ecommerce-product-pages/): identifies descriptive product names, recognizable images, price, selectable options, availability, concise product information, and clear Add-to-Cart feedback as core product-page content.

## UX problems prioritized

1. **Figma and production behavior conflict.** The Figma drawer and interaction board describe draft selections, Apply, Cancel, a modal focus trap and Escape cancellation. The current C03 implementation applies each facet immediately to the URL through the existing disclosure panel. Designing to the current code means the modal/draft contract should not be preserved unless the product behavior is deliberately changed in code and spec first.
2. **The current Figma facet set is incomplete.** The mobile design omits Bible type, language, binding, price range and in-stock status, all of which exist in the current listing schema and UI.
3. **“Print size” is not the complete variant/filter model.** The schema exposes `largePrint` as a boolean facet, while the actual product variant also has `printSize`, `fontSizePt`, binding and translation. The design must not imply arbitrary print-size values are currently filterable.
4. **Accessibility notes are based on the wrong interaction pattern.** A non-modal disclosure should not be documented as a modal with a focus trap and Escape-to-cancel behavior. The design still needs semantic groups, a correctly named disclosure control, visible keyboard focus and usable touch targets.
5. **Product-card and PDP facts must remain consistent.** Translation, binding, print size, type size, ISBN, price and stock are variant data. Missing fields must not be filled with guessed values.

## Decisions and assumptions

- The existing C03 implementation is the working behavior reference for this parity pass. Changing it to a modal/draft/apply model would require an explicit code/spec change and is outside this Figma-only run.
- Translation and binding options are API-derived; fallback values are only for the network-failure case. Bible type values are currently Study, Devotional and Children.
- The build spec describes proposed commercial rules. No prices, shipping conditions, inventory counts or policies are treated as confirmed by this UX report.
- The 27 November 44px target and visible-focus requirements remain valid design constraints, but the focus-trap/Escape-cancel behavior needs to be reconsidered for the non-modal disclosure.
