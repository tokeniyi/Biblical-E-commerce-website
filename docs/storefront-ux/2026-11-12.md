## Evidence and references

- [Baymard — Applied Filters Overview](https://baymard.com/research-articles/how-to-design-applied-filters): filtered product lists need visible selected criteria and easy removal; mobile can use scrolling chips or stacked filters.
- [Baymard — Ecommerce Filter UI](https://baymard.com/blog/ecommerce-filter-ui): mobile drawer with explicit apply, reset, and visible selected filters; URL persistence for back navigation.
- [Baymard — Product list and filtering](https://baymard.com/research-articles/current-state-product-list-and-filtering): selected-filter overview reduces loss of context.
- [Christianbook — Bible translations](https://www.christianbook.com/page/bibles/translations/): real retailer groups browsing by Bible translation, supporting the translation facet as a prominent discovery dimension.

These references inform UI patterns; they do not confirm store inventory, pricing or live result counts.

## UX problem prioritized

Existing mobile catalog exploration did not sufficiently show how a shopper can review and remove active filters without reopening the filter interface, nor how to recover from a zero-result combination. This matters especially for translation and print-size selections.

## Actual editable Figma changes

1. Added 390 × 900 mobile applied-filter catalog frame `21:2`: visible ESV and Large print filter chips, individual remove affordances, Clear all, filters/sort controls and illustrative results.
2. Added 390 × 900 mobile filter drawer frame `21:33`: translation and print-size choices, a selected-state summary, Reset, and explicit Show results confirmation. Selection remains illustrative/draft rather than live.
3. Added 390 × 900 no-match recovery frame `21:63`: active chips, explanatory empty state, Clear all and remove-one-filter recovery.
4. Preserved the repository's Inter, blue `#2563EB`, neutral surfaces and restrained corner treatment. All results and imagery are placeholders; no prices or stock were invented.

## Validation and limitations

- Figma write returned IDs `21:2`, `21:33`, `21:63`; separate page metadata confirms all three editable frames at 390 × 900.
- **Not verified:** pixel-level screenshot QA for these new frames, clipping, contrast calculations, keyboard/focus behavior, functional filter state transitions, API-backed result counts, intermediate responsive widths, and real-user testing.
- These are static state explorations, not interactive production filters. No application code changed.
