## Research and references

- [Baymard — Ecommerce filter UI](https://baymard.com/blog/ecommerce-filter-ui) — mobile filtering benefits from explicit Apply, visible applied selections, and clear recovery; avoid disruptive live updates inside the mobile drawer.
- [Baymard — Applied filters overview](https://baymard.com/research-articles/how-to-design-applied-filters) — visible selections reduce confusion and allow quick removal; the overview should not be only a numeric count.
- [Christianbook — Bible filters](https://www.christianbook.com/apps/easyfind?N=210406+1029236+4294862828) — live category navigation includes translation, binding and format facets. This is reference vocabulary, **not** proof of our inventory.

## Problem prioritized

The prior static filter states describe state transitions but not accessible focus, announcements, or differentiated no-results versus network-error recovery. That leaves keyboard and assistive-technology behavior underspecified.

## Actual editable Figma changes

Created **Catalog · Mobile · Accessible filter focus and announcements · 14 Nov 2026** (`24:2`), a 1160 × 1040 annotated static board with three columns:
1. Drawer open: initial focus on Close, focus containment, Escape cancels draft and restores the opener.
2. Apply and loading: URL facets commit and page resets to 1; polite loading announcement, with count announced only when data is available.
3. Empty/retry: clear-all and individual-filter recovery; distinguish no results from a network error (error uses an alert).

The board is deliberately illustrative, uses blue `#2563EB` with neutral backgrounds and Inter, and asserts no invented product counts. It does not implement working focus management.
